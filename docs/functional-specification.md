# [기능상세] AI 멀티 채널 콘텐츠 배포 시스템 (MCB)

## 1. 멀티 계정 관리 (Multi-Account Management)

**계정 연동 플로우**

1. 사용자가 대시보드에서 "계정 추가" 버튼 클릭
2. 플랫폼 선택 (YouTube / Instagram / TikTok)
3. 해당 플랫폼 OAuth 인증 화면으로 리다이렉트
4. 인증 완료 후 Access Token + Refresh Token 암호화 저장
5. 계정 목록에 추가, 상태 표시 (활성/토큰 만료/오류)

**토큰 자동 갱신 로직**

- Cron Job이 매일 토큰 만료일 확인 (만료 7일 전부터 갱신 시도)
- 갱신 성공: 새 토큰 암호화 저장, 상태 "활성"으로 유지
- 갱신 실패: 상태 "토큰 만료"로 변경, 사용자에게 재인증 알림 (이메일 + 대시보드 알림)
- 3회 연속 실패 시 계정 비활성화, 해당 계정으로의 예약 업로드 일시 중지

**계정 그룹 (Account Groups)**

소셜 계정을 *플랫폼별 평면 나열*이 아니라 사용자가 정의한 그룹으로 묶어 관리한다. 마이그레이션 0009 기준.

- **데이터 모델 — 1:N 관계** (한 계정 = 그룹 0~1개 소속, "그룹 미지정" 허용)
  - `account_groups (id, organization_id, name, description, color, created_by, created_at, updated_at)`
  - `social_accounts.group_id uuid NULL references account_groups.id ON DELETE SET NULL`
  - `(organization_id, name)` 유니크 — 같은 조직에서 그룹 이름 중복 금지
- **권한**: ADMIN/MANAGER만 그룹 CRUD/계정 이동 가능 (RLS 정책으로 강제). STAFF는 조회만.
- **사용 시나리오**:
  - "A브랜드", "B브랜드" 식 브랜드별 묶음
  - "글로벌팀", "한국팀" 식 팀 단위
  - "11월 캠페인" 식 임시 그룹화
- **삭제 정책**: 그룹을 삭제하면 소속 계정의 `group_id`만 NULL로 풀림 (계정 자체는 보존). `ON DELETE SET NULL` 제약으로 보장.
- **UI** (`/accounts`):
  - 그룹 카드(색상 헤더 + 이름 + 설명) 안에 소속 계정 목록
  - "그룹 미지정" 카드 별도 표시 (점선 테두리)
  - 각 계정 카드에 inline `<select>`로 즉시 그룹 이동
  - 우측 상단 "그룹 만들기" 버튼 → 인라인 폼 (이름/설명/색상 7가지)
- **마법사 연동**: §4.2 Step 1에서 그룹 단위 또는 개별 단위 선택 모드 토글 제공.

## 2. AI 캡션 최적화 (AI Caption Engine)

**"OpenAI GPT-4o의 Vision 및 언어 모델을 결합한 지능형 엔진입니다."**

**플랫폼별 캡션 전략**

| **플랫폼** | **제목/타이틀** | **설명/캡션** | **해시태그** | **특이사항** |
| --- | --- | --- | --- | --- |
| **YouTube** | 100자 이내 SEO 키워드 포함 | 5,000자 이내 타임스탬프, CTA 포함 | 최대 30개 관련성 높은 순 | 카테고리 자동 추천 |
| **Instagram** | - | 2,200자 이내 스토리텔링 형식 | 최대 30개 트렌드 + 니치 태그 | 릴스 커버 텍스트 별도 |
| **TikTok** | - | 300자 이내, 해시태그를 본문 안에 인라인으로 작성 (TikTok 실제 UX) | 최대 5개, 본문에서 자동 추출되어 검색 메타로 저장 | hook/사운드 필드 없음 |

**AI 캡션 생성 플로우**

1. 업로드 마법사 Step 1에서 게시 대상 계정(플랫폼) 확정 → Step 2에서 미디어 업로드
2. Step 3에서 "AI 자동 생성" 모드 선택 후 기본 설명/프리셋 입력
3. OpenAI에 **선택된 플랫폼만 대상**으로 프롬프트 전송 (3개 모두 선택 시 3개 동시 생성)
4. 각 플랫폼에 맞는 캡션 초안 생성 후 플랫폼별 탭으로 미리보기 표시
5. 사용자가 수정 또는 재생성 가능. 직접 작성 모드로 전환도 가능
6. Step 4 최종 검토 후 Step 5에서 업로드 진행

**캡션 프리셋**

사용자가 자주 사용하는 캡션 스타일을 프리셋으로 저장할 수 있습니다. 예를 들어 "제품 리뷰형", "튜토리얼형", "이벤트 홍보형" 등의 템플릿을 만들어 두면 반복 작업 시 효율이 높아집니다.

## 3. 최적 시간 자동 업로드 (Smart Scheduler)

**시간 최적화 로직 (3단계)**

1. **1단계 - 통계 기반 추천:** 초기에는 플랫폼별 일반적인 최적 시간 통계 데이터를 기반으로 추천합니다.
2. **2단계 - 계정별 분석:** 각 계정의 과거 게시물 성과 데이터(조회수, 좋아요, 댓글)를 분석하여 계정별 최적 시간을 학습합니다.
3. **3단계 - AI 예측:** OpenAI를 활용하여 콘텐츠 유형, 계정 특성, 요일/시즘성을 종합 분석해 최적 업로드 시간을 예측합니다.

**예약 업로드 처리 흐름**

1. 사용자가 "최적 시간 자동" 선택 또는 직접 시간 지정
2. 선택된 계정별로 최적 시간 계산 (AI 분석)
3. BullMQ에 예약 작업 등록 (delayed job)
4. 예약 시간 도래 시 Worker가 업로드 실행
5. 성공/실패 결과 기록 및 사용자 알림

## 4. 화면 구성 (UI/UX Layout)

### 4.1 화면 목록

| **No** | **화면명** | **주요 기능** | **비고** |
| --- | --- | --- | --- |
| 1 | **로그인/회원가입** | 이메일/소셜 로그인, 회원가입 | Supabase Auth 연동 |
| 2 | **대시보드** | 업로드 현황, 계정 상태, 최근 활동 | 메인 화면 |
| 3 | **계정 관리** | 플랫폼별 계정 추가/삭제/상태 확인 | 토큰 상태 모니터링 |
| 4 | **업로드 생성** | 계정 선택 → 미디어 업로드 → 캡션 → 검토 → 예약 | 핵심 화면 (5-step) |
| 5 | **업로드 목록/상세** | 업로드 이력, 상태, 계정별 결과 확인 | 필터/검색 지원 |
| 6 | **캡션 프리셋 관리** | AI 캡션 템플릿 생성/수정/삭제 | 캡션 스타일 커스터마이징 |
| 7 | **분석/통계** | 계정별 성과 데이터, 최적 시간 분석 결과 | §7 참조 (Phased: Phase 1 골격 → Phase 2 데이터) |
| 8 | **설정** | 프로필, 알림 설정, API 키 관리 | 관리자 설정 |

### 4.2 핵심 화면 상세 - 업로드 생성 화면 (5-Step Wizard)

업로드 생성 화면은 5개 스텝으로 구성된다. **계정 선택을 최우선으로 두고** 최종 검토 단계를 추가한 구조다. 계정(플랫폼)이 먼저 확정되어야 이후 파일 검증 조건, AI 캡션 생성 대상, 예약 옵션이 결정되기 때문이다.

```
Step 1 계정 선택 → Step 2 미디어 업로드 → Step 3 캡션 작성 → Step 4 최종 검토 → Step 5 예약 및 업로드
```

**스텝 간 데이터 흐름**

| 스텝 | 입력 | 산출물 (다음 스텝에 전달) |
|------|------|--------------------------|
| 1. 계정 선택 | — | `selectedAccounts[]`, `selectedPlatforms[]` (중복 제거) |
| 2. 미디어 업로드 | `selectedPlatforms` | `mediaPaths[]`, `analyzePaths[]`, `mediaMetadata` |
| 3. 캡션 작성 | `selectedPlatforms`, `analyzePaths`, `mediaMetadata` | 플랫폼별 캡션 객체 |
| 4. 최종 검토 | 위 모든 것 | 검증 통과 여부 |
| 5. 예약 및 업로드 | 위 모든 것 + `scheduledFor` | `publish_jobs` 레코드 |

**공통 사항**

- 진행 중 언제든 **이전 스텝으로 자유 이동** 가능. 단, 이전 스텝의 데이터를 수정하면 그 이후 스텝의 산출물(특히 AI 캡션)은 stale로 표시되어 재확인이 필요하다.
- 새로고침 시 작업 손실이 크므로, Step 2 완료 후부터 `contents` 테이블에 **draft 상태로 임시 저장**한다 (`status=DRAFT`). 마법사 진입 시 미완료 draft가 있으면 이어서 진행할지 묻는다.
- 각 스텝의 실패는 인라인 에러 메시지로 표시하고, 마법사 자체는 닫히지 않는다.

**내부 타이틀 (관리자용 식별 라벨)**

마법사 카드 헤더에 항상 표시되는 한 줄 입력란. 사용자가 어느 스텝에서든 자유롭게 수정 가능하다.

- **목적**: 보관함, 포스팅 관리, 분석 리포트에서 콘텐츠를 빠르게 식별하기 위한 *내부 관리용* 메타데이터. 외부에 노출되는 플랫폼 캡션 제목(YouTube `title`, Instagram `cover_text` 등)과 의미상 분리된다.
- **예시**: "한강 카페 1편", "1월 신년 시리즈 #3", "제품 X 출시 영상"
- **저장 위치**: `contents.internal_title TEXT NULL`
- **표시 폴백**: 미입력 시 보관함/포스팅 관리/분석의 라벨은 자동 생성 — 첫 플랫폼 캡션의 30자 미리보기 (`youtube.title` → `instagram.caption` → `tiktok.caption` 우선순위).
- **검색 인덱스**: 보관함·포스팅 관리의 키워드 검색 대상에 포함된다.
- **권한**: 작성자 + ADMIN/MANAGER가 수정 가능 (RLS는 contents 기존 정책 그대로).

#### Step 1 — 계정 선택

사용자가 콘텐츠를 배포할 플랫폼 계정을 선택하는 단계. 이 단계에서 선택된 플랫폼 조합이 이후 모든 스텝의 동작 조건을 결정한다.

**한 화면에서 그룹 단위 + 개별 선택 동시 가능** (별도 모드 토글 없음):

- 화면은 §1 "계정 그룹"별로 섹션을 구성하고, "그룹 미지정" 섹션이 마지막에 위치.
- 각 섹션의 **헤더에 체크박스가 있어 그 그룹의 *활성* 계정 전체를 한 번에 선택/해제** 가능. 헤더 체크박스는 indeterminate(부분 선택) 상태도 표현.
- 각 섹션 안에 소속 계정들이 개별 체크박스 행으로 노출되어, 사용자는 동일 화면에서 개별 선택/해제도 자유롭게.
- 비활성(토큰 만료 등) 계정은 disabled 처리되며 그룹 일괄 선택에서도 자동 제외.
- 그룹 헤더에 현재 선택 상태가 `N/M` 형태(선택/활성)로 노출.

**공통:**
- 연동된 계정이 0개면 "계정 추가" CTA로 `/accounts`로 유도.
- 최소 1개 이상의 계정을 선택해야 다음 스텝으로 진행 가능.
- 선택 결과는 `selectedAccounts` 배열로 다음 스텝에 전달되며, 여기서 `selectedPlatforms` (중복 제거된 플랫폼 목록)도 파생된다.
- 선택 변경 시 이미 생성된 캡션은 stale 처리(§4.2 공통 사항).

---

#### Step 2 — 미디어 업로드

선택된 플랫폼의 업로드 제약 조건에 맞춰 파일을 업로드하고 검증하는 단계.

**업로드 방식**

- 드래그 앤 드롭 영역 제공
- 영상 1개 또는 이미지 최대 10장 업로드 가능
- 업로드된 파일은 Supabase Storage(`media` 버킷)에 저장. Instagram API가 공개 URL을 요구하므로, 게시 시점에는 **단기 서명 URL**(예: 1시간 만료)을 생성해 Meta에 전달한다.
- AI 분석용으로는 별도의 `analyzePaths`를 저장한다 (영상의 경우 첫 프레임 추출 이미지, 이미지의 경우 원본 경로 그대로).

**파일 검증**

- 선택된 플랫폼 중 가장 엄격한 조건을 기준으로 검증
- 검증 실패 시 어떤 플랫폼의 어떤 조건에 위배되는지 구체적으로 안내
- TikTok만 선택한 경우 이미지 업로드 불가 안내 (TikTok Content Posting API는 영상만 지원)
- TikTok + Instagram 동시 선택 시: 이미지 캐러셀은 TikTok 게시 불가이므로 TikTok 계정을 자동으로 비대상 처리하거나 사용자에게 분기 선택 요구

| 항목 | 영상 |
|------|------|
| 해상도 | 1080×1920 (1080p) 권장. 4K 업로드 가능하나 1080p로 자동 압축 |
| 비율 | 9:16 (세로 전체화면). 16:9, 1:1도 지원하나 검은 여백 발생 |
| 포맷 | MP4 (H.264 + AAC) 권장, MOV 지원 |
| 프레임레이트 | 30fps 권장. 60fps 지원하나 압축 강도 증가 |
| 최대 파일 크기 | iOS 287.6MB, Android 72MB, 웹 업로드 시 더 큰 파일 가능 |
| 최대 길이 | 업로드 60분, 앱 내 촬영 10분. 알고리즘 최적 구간 21~34초 |
| 비트레이트 | 8~15Mbps VBR 권장. 5Mbps 미만 시 품질 저하 플래그 |
| 오디오 | AAC-LC, 44.1kHz, 256kbps 스테레오 |
| 특이사항 | Content Posting API는 영상만 지원 (이미지 업로드 불가). API 미심사 상태에서는 비공개(private) 모드로만 게시됨 |

**공통 검증 규칙 (적용 순서)**

1. 파일 포맷 확인 — 선택된 모든 플랫폼이 지원하는 포맷인지
2. 파일 크기 확인 — 선택된 플랫폼 중 가장 작은 제한 기준 적용
3. 해상도/비율 확인 — 권장 사양 미충족 시 경고(업로드 차단은 아님)
4. 영상 길이 확인 — 플랫폼별 최대 길이 초과 여부
5. **TikTok 포함 시 영상 전용 강제** — 이미지/영상 토글에서 이미지 버튼 비활성화하고 "TikTok은 영상만 업로드 가능합니다" 안내 문구 표시. 다른 플랫폼만 선택했다가 TikTok을 추가하면 자동으로 영상 모드로 전환되며 기존 업로드한 이미지는 비워진다.

**미리보기 표시 항목**

- 썸네일 자동 생성 (영상: 첫 프레임 캡처, 이미지: 원본 축소)
- 파일 기본 정보: 파일명, 용량, 해상도, 비율
- 영상인 경우: 길이, 코덱, 프레임레이트
- 플랫폼별 적합성 뱃지: 각 플랫폼 아이콘 + ✅ 적합 / ⚠️ 경고(권장 미충족) / ❌ 부적합(업로드 불가)

#### Step 3 — 캡션 작성

선택된 플랫폼별로 캡션을 작성하는 단계. **AI 자동 생성**과 **직접 작성** 두 가지 모드를 제공하며, 두 모드는 상호 전환 가능하다.

**작성 모드 선택**

- 상단에 **"AI 자동 생성 / 직접 작성"** 토글 배치
- 기본값은 "AI 자동 생성"
- 모드 전환 시 기존 작성 내용을 유지할지 묻는 확인 다이얼로그 표시

**AI 자동 생성 모드**

1. 기본 설명 입력란 — 콘텐츠에 대한 간단한 설명 또는 키워드 입력
2. 캡션 프리셋 선택 (선택사항) — "제품 리뷰형", "튜토리얼형", "이벤트 홍보형" 등 저장된 프리셋 드롭다운
3. "캡션 생성" 버튼 클릭 시 OpenAI GPT-4o에 요청
   - Vision: 업로드된 영상/이미지를 분석하여 콘텐츠 맥락 파악
   - 선택된 플랫폼만 대상으로 캡션 생성 (예: Instagram + TikTok만 선택 시 YouTube 캡션은 생성하지 않음)
   - 플랫폼별 캡션 전략 적용 (글자수 제한, 해시태그 수, 형식)
4. 생성 완료 후 플랫폼별 탭으로 결과 표시
5. "재생성" 버튼으로 다시 생성 가능

**직접 작성 모드**

1. 선택된 플랫폼별 탭에 빈 입력 필드 표시
2. 각 탭에 제목(YouTube만), 설명/캡션, 해시태그 입력란 분리
3. "다른 플랫폼에서 복사" 버튼 — 한 플랫폼에 작성한 내용을 다른 탭에 복사
4. 직접 작성 중에도 "AI로 생성해보기" 버튼을 통해 AI 모드로 전환 가능

**공통 편집 기능 (모드 무관)**

- 플랫폼별 탭 UI — 선택된 플랫폼만 탭으로 표시
- 글자수 실시간 카운터 (플랫폼별 제한 대비 현재 글자수)
  - YouTube 제목: 100자, 설명: 5,000자
  - Instagram 캡션: 2,200자
  - TikTok 캡션: 300자 (4,000자 - 2024년 확장, 확인 필요)
- 해시태그 입력 및 카운터
  - YouTube: 최대 30개 (별도 입력란)
  - Instagram: 최대 30개 (별도 입력란)
  - TikTok: 별도 입력란 없음 — 본문 안에 `#`로 직접 작성. 저장 시 자동 추출되어 hashtags 메타데이터에 채워짐 (최대 5개 권장)
- 글자수 초과 시 경고 표시 (빨간색 카운터 + 경고 메시지)
- 각 플랫폼 캡션을 개별적으로 수정 가능

캡션 전략 상세는 `## 2. AI 캡션 최적화` 섹션을 참조한다 (단일 출처 원칙).

#### Step 4 — 최종 검토

업로드 실행 전 모든 설정을 한눈에 확인하는 단계. 3개 플랫폼 일괄 배포의 실수를 방지하기 위한 안전장치다.

**표시 항목**

- **미디어 미리보기** — 업로드한 영상/이미지 썸네일
- **계정별 카드 목록** — 선택된 각 계정에 대해:
  - 플랫폼 아이콘 + 계정명
  - 해당 플랫폼 캡션 미리보기 (제목, 본문 앞부분, 해시태그 수)
  - 파일 적합성 상태 (✅ / ⚠️)
- **수정 필요 시** — 각 섹션 옆 "수정" 링크 클릭 시 해당 스텝으로 이동 (이전 스텝 자유 이동 가능)

**검증**

- 글자수 초과 항목이 없는지 확인
- 파일 부적합(❌) 계정이 있으면 해당 계정 제외 또는 파일 변경 안내
- 검증 통과 시 "다음" 버튼 활성화

#### Step 5 — 예약 및 업로드

업로드 방식을 선택하고 실행하는 최종 단계.

**업로드 방식 선택**

- **즉시 업로드** — 확인 즉시 모든 선택 계정에 업로드 시작
- **예약 업로드** — 날짜/시간을 지정하여 예약
  - **최적 시간 자동** — AI가 계정별 과거 성과 데이터를 분석하여 최적 시간 추천 (Smart Scheduler 섹션 참조)
  - **직접 지정** — 달력 + 시간 피커로 수동 지정 (계정별 개별 시간 설정 가능)

**업로드 처리 흐름**

1. "업로드" 또는 "예약" 버튼 클릭
2. 각 계정별 `publish_jobs` 레코드 생성 (DB, 상태 PENDING / SCHEDULED)
3. BullMQ에 작업 등록 (즉시: 즉시 실행 / 예약: delayed job)
4. Worker가 플랫폼별 API 호출하여 업로드 실행 (계정 토큰을 service_role로 복호화)
5. 계정별 업로드 상태 실시간 표시:
   - 대기 → 진행중 → 완료 / 실패
   - 실패 시 에러 메시지 + 재시도 버튼
6. 모든 계정 처리 완료 시 결과 요약 표시
7. 결과 알림 (대시보드 알림 + 이메일)

**상태 표시 UI**

- 계정별 카드에 프로그레스 인디케이터
- 상태 뱃지: 대기(회색) / 진행중(파란색 스피너) / 완료(초록색 체크) / 실패(빨간색 X)
- 전체 진행률 표시 (예: 2/3 완료)

## 5. API 연동 상세 (API Deep Dive)

### 5.1 YouTube Data API v3

- **업로드:** insert — 영상 또는 이미지(최대10장) + 메타데이터 설정
- **예약:** insert의 publishAt 파라미터로 예약 게시 (status: private → 예약 시간에 public)
- **할당량:** 일 10,000 units (영상 또는 이미지(최대10장)는 1,600 units 소모)
- **제한:** 일일 업로드 수 제한 있음 (6개 계정 × 6개 = 약 36건/일)

### 5.2 Instagram Graph API

- **업로드:** POST /me/media → POST /me/media_publish (2단계)
- **지원 형식:** 릴스(Reels), 이미지, 캐러셀 (영상은 리스로 업로드)
- **예약:** API 예약 게시 미지원 — BullMQ delayed job으로 예약 처리
- **제한:** 비즈니스/크리에이터 계정 필수, Meta 앱 심사 필요

### 5.3 TikTok Content Posting API

- **업로드:** POST /v2/post/publish/video/init → chunk upload → publish
- **지원 형식:** 영상 (mp4, 최대 4GB, 최대 10분)
- **예약:** API 예약 게시 미지원 — BullMQ delayed job으로 처리
- **제한:** API 접근 승인 필요, 승인 난이도 높음

### 5.4 대안: 서드파티 API 우회

Instagram과 TikTok의 공식 API 승인이 어려울 경우, Buffer API 또는 Hootsuite API를 통해 우회 연동하는 방안을 병행 검토합니다. 이 경우 추가 구독 비용이 발생할 수 있습니다.

## 6. 배포 관리 (Posting Management)

### 6.1 개요
업로드된 모든 콘텐츠의 상태를 한눈에 파악하고, 필터/검색/일괄 작업을 수행하는 관리 화면. 대시보드 사이드바 네비게이션의 "콘텐츠 > 배포 관리" 메뉴로 진입한다 (§9). 경로는 `app/(dashboard)/postings/page.tsx`.

> 본 문서에서 "포스팅 관리"는 사용자 노출 메뉴명이 §9 사이드바 재편 이후 "배포 관리"로 바뀌었다. 본문 내 다른 위치에서 "포스팅 관리"로 표기된 부분은 모두 같은 화면을 가리킨다.

데이터 소스: **`publish_jobs` 테이블** 기준 (기존 스키마. 외부 명세 문서에서 *upload_targets*로 부르기도 하지만 코드/마이그레이션상 일관된 이름은 `publish_jobs`). `contents` 테이블과 JOIN하여 미디어/캡션 정보, `social_accounts` 테이블과 JOIN하여 계정/플랫폼 정보를 함께 표시.

**status 값 매핑** (기획서 표기 → 실제 enum + 보조 컬럼):
- 대기 (pending) → `status='PENDING'` AND `scheduled_for IS NULL`
- 예약중 (scheduled) → `status='PENDING'` AND `scheduled_for > now()`
- 업로드중 (uploading) → `status='PROCESSING'` (또는 `'RETRYING'`)
- 완료 (completed) → `status='SUCCESS'`
- 실패 (failed) → `status='FAILED'`
- 취소됨 (cancelled) → `status='CANCELLED'` (신규 enum 값)

### 6.2 필터 영역 (상단 고정)

**상태 필터** (다중 선택 가능, 칩 또는 토글 버튼)
- 예약중 (scheduled) — 예약 시간 대기 중
- 업로드중 (uploading) — 현재 API 호출 진행 중
- 완료 (completed) — 성공적으로 게시됨
- 실패 (failed) — 업로드 실패 (에러 메시지 포함)
- 대기 (pending) — 큐 등록 대기
- 취소됨 (cancelled) — 사용자가 예약 취소
- 기본값: 전체 선택

**플랫폼 필터** (다중 선택 가능)
- YouTube / Instagram / TikTok 아이콘과 함께 표시
- 기본값: 전체 선택

**기간 필터**
- 프리셋: 오늘 / 최근 7일 / 최근 30일 / 전체
- 또는 날짜 범위 직접 선택 (date range picker)
- 기본값: 최근 7일

**검색**
- 콘텐츠 제목, 캡션 본문, 계정명으로 키워드 검색. 디바운스 300ms.

**정렬**
- 예약 시간순 (기본값, 최신 먼저) / 생성 시간순 / 상태순 (실패 > 업로드중 > 예약중 > 대기 > 완료 > 취소됨)

### 6.3 상태 요약 카드 (목록 상단)
필터 조건에 해당하는 포스팅의 상태별 건수를 카드로 표시. 전체/예약중/업로드중/완료/실패. 실패 카드는 빨간색 강조. 카드 클릭 시 해당 상태로 필터 자동 적용.

### 6.4 목록 테이블

**컬럼 구성:**
1. 체크박스 — 일괄 작업용
2. 콘텐츠 — 썸네일(40x40) + 제목(또는 캡션 앞 30자). 클릭 시 상세 모달
3. 플랫폼 — 아이콘 (YouTube/Instagram/TikTok)
4. 계정 — 계정명 + 프로필 이미지
5. 상태 — 컬러 뱃지 (예약중=노란색, 업로드중=파란색, 완료=초록색, 실패=빨간색, 대기=회색, 취소됨=회색)
6. 예약 시간 — 예약 시간 표시. 즉시 업로드면 "즉시"
7. 게시 시간 — 실제 게시 완료 시간. 미완료면 "-"
8. 액션 — 드롭다운 메뉴 (상세보기/재시도/예약취소/삭제)

**실패 행 강조:** 배경색 연한 빨간색. 에러 메시지 1줄 축약 표시. 호버 시 전체 에러 툴팁.

**페이지네이션:** 한 페이지 20건. 무한 스크롤 또는 페이지 번호.

### 6.5 일괄 작업 (체크박스 선택 시 상단 액션바)
- 일괄 재시도 — 실패 상태 항목만 대상. 비실패 항목은 무시
- 일괄 예약 취소 — 예약중 상태만 대상. BullMQ delayed job 제거 + DB 상태 `CANCELLED` (Phase 4b 워커 활성화 전에는 DB 상태 변경만)
- 일괄 삭제 — 확인 다이얼로그 후 soft delete (`deleted_at` 타임스탬프 기록, 실제 삭제 아님)

### 6.6 상세 모달 (행 클릭 또는 상세보기)
- 콘텐츠 미디어 미리보기 (영상 플레이어 또는 이미지)
- 플랫폼별 캡션 전문 (제목, 본문, 해시태그)
- 게시 URL 링크 (완료 시 — 해당 플랫폼 게시물로 바로 이동)
- 상태 히스토리 타임라인 (pending → scheduled → uploading → completed 각 단계별 시간)
- 에러 로그 (실패 시 — 전체 에러 메시지 + 스택트레이스)
- 재시도 / 예약 취소 버튼

### 6.7 자동 새로고침
- 업로드중 또는 예약중이 1건 이상이면 10초 간격 자동 갱신
- 모든 항목이 완료/실패면 자동 갱신 중지
- 수동 새로고침 버튼도 제공

### 6.8 DB 변경사항 (마이그레이션 0007)
`publish_jobs`에 컬럼 추가:
- `cancelled_at TIMESTAMPTZ` — 예약 취소 시간
- `deleted_at TIMESTAMPTZ` — soft delete
- `status_history JSONB DEFAULT '[]'::jsonb NOT NULL` — `[{status, timestamp, message}]` 형태
- `publish_status` enum에 `'CANCELLED'` 값 추가

기존 마이그레이션과 충돌하지 않도록 새 파일(`0007_publish_jobs_management.sql`)로 처리. UPDATE 정책은 추가하지 않고 기존 패턴(서버 액션 + service_role)을 유지한다.

## 7. 분석/리포팅 (Analytics & Reporting)

### 7.1 개요
게시된 모든 콘텐츠의 성과 데이터를 자동 수집하여 시각화한다. §4.1 화면 목록의 §7 "분석/통계"에 해당. 경로는 `app/(dashboard)/analytics/page.tsx`.

**서비스 가치 측면 위치:** AI 캡션의 효과를 *측정 가능한 지표*로 입증하는 화면이다. 측정이 없으면 §2(AI 캡션 최적화)와 §3(Smart Scheduler)의 가치는 추정으로 남는다. Smart Scheduler 3단계(계정별 분석, AI 예측)의 학습 데이터 소스이기도 하다.

### 7.2 데이터 수집

**Source — 각 플랫폼 Insights API:**
- YouTube Data API v3: `videos.list` (`part=statistics,snippet`)
- Instagram Graph API: `{media_id}/insights` (impressions, reach, likes, comments, saved, shares)
- TikTok Display API: `video/query/` (insights는 별도 권한 필요)

**대상:** `publish_jobs` 중 `status='SUCCESS'` AND `platform_post_id IS NOT NULL`

**수집 주기 (감소 밀도):** 게시 후 1시간 → 6시간 → 24시간 → 7일 → 30일 시점에 폴링. cron job (Phase 4c 토큰 갱신 워커와 같이 또는 별도).

**저장 — 신규 테이블 `posting_metrics`:**
```sql
posting_metrics (
  id              uuid pk,
  publish_job_id  uuid fk → publish_jobs.id on delete cascade,
  fetched_at      timestamptz default now(),
  views           bigint,
  likes           bigint,
  comments        bigint,
  shares          bigint,
  saves           bigint,
  raw             jsonb        -- 플랫폼 원본 응답 (디버깅/스키마 변경 안전망)
)
```
인덱스: `(publish_job_id, fetched_at desc)`. RLS는 `publish_jobs`의 organization scope를 EXISTS로 위임.

### 7.3 화면 구성

#### 7.3.1 종합 대시보드 (메인)
- **기간 필터**: 최근 7일 / 30일 / 90일 / 사용자 지정
- **상단 KPI 카드**: 총 게시 수 · 총 조회수 · 총 참여(좋아요+댓글+공유+저장) · 평균 ER% (참여/조회)
- **플랫폼별 카드**: 게시 수 · 평균 조회/참여 · 전 기간 대비 증감 (↑/↓)
- **시계열 차트**: 일별 조회수·참여 (플랫폼별 stacked area 또는 line)
- **TOP 5 게시물**: 기간 내 ER 상위 5개

#### 7.3.2 콘텐츠별 상세
- 게시물 클릭 시 모달 또는 별도 페이지(`/analytics/[publishJobId]`)
- **시간대별 성장 곡선**: 1h / 6h / 1d / 7d / 30d 시점 마커
- **동일 콘텐츠 멀티 플랫폼 비교**: 같은 contentId가 여러 플랫폼에 게시된 경우 한 화면에서 비교
- **캡션 미리보기**: 어떤 카피였는지 함께 표시 (인사이트와 캡션을 분리해서 보면 무의미)

#### 7.3.3 캡션 효과 분석
- **AI 자동 vs 직접 작성** 평균 ER 비교 (히스토그램 + 표본 수)
- **캡션 길이대별 ER 분포** (산점도 또는 박스플롯)
- **해시태그 수별 ER**
- **"효과 좋은 캡션 패턴" 자동 추출** — 상위 10% 게시물의 공통 키워드/이모지/CTA 패턴 (간단한 빈도 분석부터)

#### 7.3.4 최적 시간 학습 결과
- **요일×시간 히트맵**: 계정별 평균 ER을 7×24 그리드로
- **Smart Scheduler 추천 슬롯 표시**: §3의 학습 결과가 어떤 시간대를 추천하는지 시각화
- 데이터가 부족한 셀(N<3)은 회색 처리

### 7.4 식별/그룹 단위
- 모든 차트/표의 콘텐츠 라벨은 **§4.2의 내부 타이틀(`contents.internal_title`) 우선**, 미입력 시 첫 플랫폼 캡션 앞 30자.
- 향후 캠페인/시리즈 그룹화 도입 시 그룹 단위 슬라이싱 추가.

### 7.5 알림 연동
폭발 게시 자동 감지 → §8 알림 시스템과 연동 (§8 명세 신설 시):
- 한 게시물의 ER이 *해당 계정 30일 평균의 N배(기본 5배)* 초과 시 알림
- 한 게시물의 부정적 시그널(댓글 급증 + 좋아요 정체) 감지 시 알림 (선택)

### 7.6 Export
- CSV: 게시물별 raw 데이터 (전체 컬럼)
- PDF 월간 요약 리포트 자동 생성 (cron, 매월 1일)

### 7.7 구현 단계 (Phased Rollout)
| Phase | 범위 | 상태 |
|-------|------|------|
| **Phase 1** | 화면 골격 + 빈 상태 + 사이드바 메뉴. 데이터 없음 안내 카드 표시. | **이번 작업** |
| Phase 2 | `posting_metrics` 테이블 + 수집 cron + 7.3.1 종합 대시보드 | 추후 |
| Phase 3 | 7.3.2~7.3.4 상세 분석 화면 | 추후 |
| Phase 4 | 7.5 알림 연동, 7.6 export | 추후 |

데이터 수집 cron은 Phase 4c(토큰 자동 갱신 워커)와 같은 인프라(BullMQ + Upstash Redis)를 공유한다.

## 8. 대시보드 리디자인 (Dashboard)

### 8.1 설계 원칙
대시보드는 "현황판"이 아니라 "액션 중심 허브"다. 누적 통계는 분석/통계 페이지에서 다루고, 대시보드에서는 지금 당장 확인하거나 처리해야 할 것만 보여준다.

우선순위: 문제 알림 > 오늘 할 일 > 진행 상태 > 빠른 접근

### 8.2 레이아웃 구성 (위에서 아래 순서)

**① 헤더 영역**
- 좌측: "대시보드" 타이틀 + 서브텍스트 (오늘 요약 한 줄, 예: "오늘 예약된 콘텐츠 3건, 실패 1건")
- 우측: "배포 관리" 버튼 (outline) + "콘텐츠 생성" 버튼 (primary, 강조)

**② 실패 알림바 (조건부 표시)**
- 실패 건이 1개 이상일 때만 표시. 실패 건이 0이면 이 영역 자체가 숨겨짐
- 빨간색 배경 바. 좌측에 경고 아이콘 + 실패 내용 요약 ("여름 신상 룩북 TikTok 업로드 실패 — 토큰 만료"), 우측에 "재시도 →" 링크
- 실패가 여러 건이면 "N건 실패 — 포스팅 관리에서 확인" 으로 표시

**③ 오늘 기준 숫자 카드 (4열 그리드)**
- 오늘 예약: 오늘 예약된 업로드 건수 + 서브텍스트 "다음 HH:MM" (가장 가까운 예약 시간)
- 진행중: 현재 업로드 중인 건수 + 서브텍스트 (진행중인 콘텐츠명 또는 플랫폼)
- 실패: 미처리 실패 건수 + 서브텍스트 "즉시 확인 필요" (빨간색 강조). 실패가 0이면 일반 색상
- 이번 주 완료: 이번 주 완료 건수 + 서브텍스트 "지난주 대비 +N" (증감 표시)
- 각 카드 클릭 시 해당 상태로 필터된 배포 관리 페이지로 이동

**④ 예정된 업로드 목록**
- 섹션 타이틀 "예정된 업로드" + "전체 보기 →" 링크 (배포 관리로 이동)
- 최대 5건까지 표시 (예약 시간 가까운 순)
- 각 항목: 썸네일(영상/이미지 아이콘) + 콘텐츠 제목 + 예약 시간 + 플랫폼 수 + 플랫폼 아이콘들 + 상태 뱃지
- 실패 건은 빨간 테두리 + 에러 메시지 요약으로 강조
- 빈 상태: "예정된 업로드가 없어요. 첫 콘텐츠 만들기 →"

**⑤ 연동 계정 (플랫폼별 그룹핑)**
- 섹션 타이틀 "연동 계정" + "관리 →" 링크 (계정 연동 페이지로 이동)
- 3열 그리드로 YouTube / Instagram / TikTok 카드
- 각 카드: 플랫폼 아이콘 (브랜드 컬러 배경) + 연동 계정 수 + 상태 요약
  - 상태 요약: 모두 활성이면 초록 점 + "N개 활성"
  - 토큰 만료가 있으면 빨간 점 + "N개 토큰 만료" (빨간 텍스트, 카드 테두리도 빨간색)
- 카드 클릭 시 해당 플랫폼 계정 상세로 이동
- 아직 연동 안 된 플랫폼도 카드로 표시하되 "0 계정, 연동하기" 상태

**⑥ 빠른 작업 (3열 그리드)**
- AI 프리셋 (아이콘 + 라벨) → AI 프리셋 페이지로 이동
- 계정 연동 (아이콘 + 라벨) → 계정 연동 페이지로 이동
- 배포 관리 (아이콘 + 라벨) → 배포 관리 페이지로 이동 (실패 건 필터 자동 적용 시 활용)

> §9.6에 따라 "업로드 이력" 메뉴는 제거되었다. 기존 빠른 작업 3열 중 마지막 슬롯은 배포 관리로 흡수한다.

### 8.3 데이터 소스
- 숫자 카드: `publish_jobs` 테이블에서 오늘 날짜 기준 상태별 COUNT
- 예정된 업로드: `publish_jobs` WHERE status IN ('PENDING', 'PROCESSING', 'FAILED') AND deleted_at IS NULL ORDER BY scheduled_for ASC LIMIT 5, `contents`/`social_accounts` JOIN
- 연동 계정: `social_accounts` 테이블에서 platform별 GROUP BY + 상태별 COUNT
- 이번 주 완료 증감: 이번 주 vs 지난 주 SUCCESS COUNT 비교

## 9. 사이드바 네비게이션

### 9.1 설계 원칙
메뉴 그룹은 사용자 행동 기준으로 분류한다. "내가 뭘 하려는지"에 따라 자연스럽게 찾아갈 수 있는 구조. 자주 보는 화면(대시보드, 분석)은 그룹 밖 최상단에 배치하고, 한 번 세팅하고 가끔 수정하는 것(계정 연동, AI 프리셋)은 설정 그룹으로 분리한다.

### 9.2 메뉴 구조

**최상단 (그룹 없음)**
- 대시보드 — 오늘 할 일, 실시간 현황, 액션 허브 (§8)
- 분석 — 계정별 성과 데이터, 최적 시간 분석, 리포팅 (§7)

**콘텐츠 그룹**
- 콘텐츠 생성 — 5-Step 업로드 마법사 진입 (§4.2)
- 배포 관리 — 전체 포스팅 상태 조회, 필터, 일괄 작업 (§6). 실패 건이 있으면 메뉴 옆에 빨간 숫자 뱃지 표시
- 보관함 — 생성했지만 아직 배포하지 않은 콘텐츠 **전용**. `contents`에 별도 상태 컬럼은 없고, **`publish_jobs`가 하나도 없는 행 = 초안**으로 판정한다(발행을 시도한 순간 배포 관리 관할로 넘어가 보관함에서 사라진다)

**삭제 동작 — 두 가지를 혼동하지 말 것**
- 배포 관리의 일괄 "삭제": `publish_jobs.deleted_at`만 세팅하는 **soft delete**. 목록에서 줄을 숨길 뿐 콘텐츠·미디어는 남는다
- 배포 관리 포스팅 상세의 "콘텐츠 삭제" / 보관함의 "삭제": `deleteContentsAction` — 콘텐츠 행 + Storage 미디어 + 해당 콘텐츠의 모든 `publish_jobs`(cascade)를 **영구 삭제**

개인정보처리방침·데이터 삭제 안내가 이 영구 삭제를 사용자 권리 이행 수단으로 명시하므로, **발행된 콘텐츠에도 영구 삭제 경로가 UI에 반드시 존재해야 한다**(현재는 배포 관리 → 포스팅 상세 → 콘텐츠 삭제).

**자동화 그룹**
- DM 자동 응답 — AI 기반 DM 자동 응답 (추후 구현). "soon" 뱃지 표시하고 클릭 시 coming soon 안내. 향후 GPT-4o가 캡션/브랜드 톤을 학습해 1차 응답을 작성하고 사람 핸드오프 큐로 라우팅
- 예약 규칙 — 반복 예약, 자동 배포 규칙 설정 (추후 구현). "soon" 뱃지 표시

**설정 그룹**
- 계정 연동 — OAuth 플랫폼별 계정 연결/해제/토큰 상태 관리 (§1)
- AI 프리셋 — 캡션 생성 스타일 템플릿 관리 (생성/수정/삭제) (§2 캡션 프리셋)

### 9.3 문구 변경 사항 (기존 → 변경)
- "포스팅 관리" → "배포 관리" (멀티 채널 배포 도구에 맞는 용어)
- "계정 관리" → "계정 연동" (실제 기능이 OAuth 연동이므로)
- "프리셋" → "AI 프리셋" (AI 캡션 프리셋임을 명확히)
- "업로드 이력" → 삭제 (배포 관리에 필터로 통합)
- "분석/리포팅" → "분석" (간결하게)
- "새 콘텐츠" → "콘텐츠 생성" (메뉴 라벨에 동작 의도를 명시적으로)

### 9.4 뱃지 규칙
- 배포 관리: `publish_jobs`에서 `status = 'FAILED'`이고 `deleted_at IS NULL`인 건수를 실시간 반영. 0이면 뱃지 숨김. 100 이상이면 `99+`로 축약 표시. (외부 명세에서 *upload_targets*로 부르기도 하지만 코드/마이그레이션 기준 일관된 이름은 `publish_jobs` — §6.1 참조)
- DM 자동 응답, 예약 규칙: "soon" 뱃지 고정 표시 (초록색 배경). 기능 출시 후 제거
