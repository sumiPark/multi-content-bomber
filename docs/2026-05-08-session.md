## 2. DB 스키마 (`0001_init.sql`)

**목표**: 5개 핵심 테이블 + RLS + 보안 강화

**테이블**: `organizations`, `profiles`, `social_accounts`, `contents`, `publish_jobs`

**보안 결정**:
- 토큰은 앱 레이어에서 AES-256-GCM 암호화 후 `bytea`로 저장 (DB에 키 X)
- `profiles.organization_id/role` 컬럼에 컬럼 레벨 REVOKE — 사용자가 자기 프로필을 다른 조직으로 옮기는 공격 차단
- 조직 생성은 `create_organization()` RPC로만 (직접 INSERT 차단)
- `publish_jobs` INSERT 시 content와 social_account 둘 다 호출자 org에 속하는지 검증
- 워커 UPDATE는 RLS 정책 없음 — service_role 전용

**RLS 헬퍼**: `current_org_id()`, `current_role()` SECURITY DEFINER + 잠긴 search_path

## 5. 이미지 드롭존

`react-dropzone` + lucide `ImageUp` 아이콘.

**기능**:
- 1~10장, 25MB/장 한도, JPG/PNG/WEBP만
- `URL.createObjectURL()`로 블롭 미리보기 + unmount 시 자동 revoke
- 호버 시 X 버튼으로 개별 삭제, "모두 지우기"

**`crypto.randomUUID()` 키** 사용 — 같은 파일 여러 번 추가해도 React 키 충돌 없음.

## 6. AI 캡션 (base64 단계)

OpenAI GPT-4o Vision + JSON Schema strict mode.

**캡션 스키마 (zod)**: youtube/instagram/tiktok 각각 (title|caption + hashtags + 플랫폼별 필드).

**전송 방식**: 클라이언트에서 `FileReader.readAsDataURL` → 데이터 URL → Server Action → OpenAI. Storage 도입 전 임시 방편.

**`next.config.ts`** Server Action body 한도 1MB → 10MB 임시 상향.

**Cost**: 이미지 10장 × `detail: 'low'` 85토큰 + 프롬프트 ≈ $0.012/요청.

## 9. Hydration mismatch 발견 + 수정

**증상**: "Recoverable Error" — `26. 5. 8. 오후 3:56` (브라우저) vs `26. 5. 8. PM 3:56` (서버).

**원인**: Node ICU 데이터에 ko-KR 풀데이터 부재 → 영어 fallback. 브라우저는 한국어. React가 mismatch 감지.

**해결**: `<RelativeTime iso={...} />` 클라이언트 컴포넌트로 추출. 서버는 빈 텍스트, 마운트 후 useEffect로 채움. 모든 시각 표시에 재사용.

## 10. 드래그 reorder + 보관함 + 불러오기

**삭제 버튼 + 드래그 충돌**: `e.stopPropagation()` + `onPointerDown stopPropagation` 둘 다 필요 (framer-motion이 pointerdown으로 드래그 시작 감지).

## 16. Phase 4a — OAuth 기반

**`0006_token_columns_text.sql`**: 토큰 컬럼 `bytea → text`. Supabase JS의 PostgREST가 bytea를 다루기 번거로워 base64 ciphertext를 text로 저장 (보안 동등).

**`lib/crypto.ts`**: AES-256-GCM. 포맷: `base64(iv₁₂ ‖ tag₁₆ ‖ ciphertext)`. 키는 `ENCRYPTION_KEY` env (32바이트 base64).

**`lib/supabase/service.ts`**: service_role 클라이언트. 토큰 컬럼 RLS 컬럼-레벨 revoke 우회용. 워커 + OAuth 콜백 전용.

**`lib/platforms/`**: `PlatformAdapter` 인터페이스 + Instagram + TikTok 구현. YouTube는 사용자 요청대로 제외.

**OAuth 라우트**:
- `/api/auth/connect/[platform]`: GET, state 쿠키 발급(httpOnly, 5분), 프로바이더 redirect
- `/api/auth/callback/[platform]`: GET, state 검증, `exchangeCode`, 토큰 암호화, service_role upsert

**`/accounts` 업데이트**: placeholder → 실제 connect 링크 + 연결 해제 버튼 + `?connected=...`/`?error=...` 배너. ADMIN/MANAGER만 관리.

## 17. Instagram OAuth 디버깅

**이슈 1: `INSTAGRAM_CLIENT_ID 환경변수 없음`**
- 원인: 코드는 OAuth 표준 용어(client_id), Meta 콘솔은 "App ID"로 표시. 사용자 혼란.
- 해결: env 변수 `INSTAGRAM_APP_ID/SECRET`로 개명 (Meta UI와 일치).

**이슈 2: `Invalid redirect_uri`**
- 원인: Instagram Business Login은 HTTPS 필수 + localhost 차단. 우리는 `http://localhost:3000/...` 송신 중.
- 해결안: Cloudflare Tunnel(`cloudflared tunnel --url http://localhost:3000`) → HTTPS URL 받기 → `NEXT_PUBLIC_SITE_URL` 갱신 → Meta 콘솔에 동일 URL 등록 → dev 재시작.
- 디버그용 로그 한 줄 추가 (`console.log('[oauth connect] platform=... redirect_uri=...')`).
