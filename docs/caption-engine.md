# AI 캡션 엔진 프롬프트 설계서

## 개요

MCB의 AI 캡션 생성에서 OpenAI GPT-4o API에 전달할 프롬프트 구조와 클릭/체류/저장을 유도하는 카피라이팅 원칙을 정의한다. 개발자는 `lib/ai/caption-generator.ts`와 `lib/ai/prompts.ts`를 이 문서를 단일 출처로 참조하여 구현한다.

설계 목표:
1. **메시지 일관성** — 한 콘텐츠에 대해 플랫폼별 톤은 다르되 핵심 메시지는 동일.
2. **알고리즘 시그널 최적화** — 각 플랫폼의 추천 알고리즘이 우대하는 행동(클릭, 체류, 저장, 댓글)을 유도하는 카피.
3. **재현성** — 같은 입력에 비슷한 품질, 다른 입력에 명확히 다른 결과.

---

## 클릭/체류/저장을 만드는 8가지 원칙 (근거 기반)

캡션은 단순히 정보를 전달하는 것이 아니라, 사용자의 다음 행동(스크롤 멈춤 → 시청 → 댓글/저장/공유)을 설계하는 도구다. 아래 원칙은 인지심리학·행동경제학·플랫폼 알고리즘 데이터에 근거한다. AI 생성 시 이 원칙들을 명시적으로 시스템 프롬프트에 주입한다.

### 1. Curiosity Gap (정보 격차)

> *"답을 주지 말고 답이 있다는 것만 보여줘라."*
> — Loewenstein (1994), "The Psychology of Curiosity"

**메커니즘:** 인간은 알고 있는 것과 모르는 것 사이의 *격차*를 인지하면 그 격차를 메우려 한다. 결과는 보여주되 *방법/이유*는 숨긴다.

**실행:**
- 결과/숫자는 노출, 과정은 숨김. "한 달에 30만원 절약한 방법" (X 30만원 절약하는 5단계 가이드)
- 전체의 30% 정보만 흘리기

**적용 플랫폼:** YouTube 제목, Instagram 첫 줄, TikTok 훅

### 2. Specificity Bias (구체성 편향)

> *"숫자가 추상을 이긴다."*

**메커니즘:** 구체적인 숫자/이름/시간은 추상적 표현보다 신뢰도와 기억률이 높다 (Schindler & Yalch, 2006).

**실행:**
- "큰 절약" → "287만원 절약"
- "많은 분들이" → "1,247명이"
- "오래 걸렸어요" → "3개월 걸렸어요"
- 정확한 숫자가 없으면 어림수도 OK ("약 50명")

**적용 플랫폼:** 모두

### 3. Loss Aversion (손실 회피)

> *"잃는 고통은 얻는 기쁨의 약 2배."*
> — Kahneman & Tversky, Prospect Theory (1979)

**메커니즘:** 같은 가치라도 잃을 위험을 강조할 때 행동 유도력이 강하다.

**실행:**
- "꼭 보세요" → "놓치면 후회하는"
- "할인 시작" → "오늘 자정 종료"
- 단, 거짓 긴박감은 금지 (어그로). 실제 한정성·시즌성·실수의 비용일 때만.

**적용 플랫폼:** YouTube 제목, Instagram 첫 줄

### 4. Pattern Interruption (패턴 중단)

> *"예측을 깨면 시선이 멈춘다."*

**메커니즘:** 뇌는 패턴을 빠르게 예측한다. 의외성·역설·모순은 자동 주의(automatic attention)를 끈다. TikTok처럼 1초에 시청 결정이 나는 플랫폼에서 결정적.

**실행:**
- 일반적 표현 회피: "맛있는 카페" → "카페에서 라면을 시켰다"
- 역설/모순: "공부 안 하고 1등 한 비결"
- 갑작스러운 전환: "...라고 생각했는데"

**적용 플랫폼:** TikTok 훅 (최우선), Instagram Reels 커버

### 5. Open Loop / Cliffhanger

> *"미완성은 기억된다."*
> — Zeigarnik 효과 (1927)

**메커니즘:** 미완성된 정보는 완성된 정보보다 훨씬 잘 기억되고 끝까지 보고 싶게 만든다. 시청 지속률(YouTube AVD, IG Reels 완료율)에 직접 기여.

**실행:**
- "끝까지 보면 진짜 비밀이 나옵니다" 식 텍스트 hook
- "그런데 이게 끝이 아니에요"로 영상 중반 텐션 유지 신호 (캡션에서 예고)

**적용 플랫폼:** YouTube 설명, Instagram Reels 캡션

### 6. First-Line Hook (Instagram "더보기" 유도)

**메커니즘:** Instagram 알고리즘은 *Engaged Time*(체류시간)을 강한 신호로 본다. 캡션 첫 줄 후 "더보기"를 누르면 체류가 늘고 노출이 확대된다.

**실행:**
- 첫 줄에 강한 감정·질문·숫자 배치
- 첫 줄 끝에 마침표 X, 줄임표(...) 또는 의도적 단절
- 예: "이거 모르고 3년을 낭비했어요..."

**적용 플랫폼:** Instagram 캡션 (필수)

### 7. Question-Driven CTA (질문형 마무리)

**메커니즘:** 댓글은 모든 플랫폼에서 강한 알고리즘 신호. 질문은 평서문 CTA보다 댓글률을 1.5~2배 올린다 (Buffer 2023 자료).

**실행:**
- "여러분은 어떻게 하세요?", "이 중에 뭐가 제일 끌려요?"
- 답하기 쉬운 폐쇄형 질문이 개방형보다 응답률 높음
- "댓글 남겨주세요" 식 명령형은 비추 (모든 SNS 알고리즘이 디스카운트)

**적용 플랫폼:** Instagram 캡션, YouTube 설명

### 8. Save-Worthy Framing (저장 유도)

**메커니즘:** 저장(saves)은 Instagram·TikTok 알고리즘에서 좋아요보다 가중치가 높다. "나중에 다시 볼 가치"가 있다는 시그널이기 때문.

**실행:**
- "리스트", "정리", "한 번에", "총정리" 키워드
- "이거 저장해놓고 두고두고 보세요" 식 명시 CTA (단, 자연스럽게)
- 정보성·가이드성 콘텐츠일수록 효과 큼

**적용 플랫폼:** Instagram 캡션, TikTok 본문

## 플랫폼 알고리즘 시그널 우선순위 (참고)

| 플랫폼 | 1순위 신호 | 2순위 | 3순위 | 캡션이 영향 주는 정도 |
|--------|------------|-------|-------|------------------|
| **YouTube Shorts** | 시청 완료율 (Watched %) | CTR (제목/썸네일) | 좋아요/댓글 | 중간 (제목이 CTR 좌우) |
| **Instagram** | Engaged Time + 저장 | 공유 | 댓글 | 큼 (캡션 첫 줄이 체류 결정) |
| **TikTok** | 완료율 + 재시청률 | 공유 | 댓글 | 작음 (영상이 핵심, 캡션은 보조) — 단 첫 단어가 훅 역할 |

## 프롬프트 아키텍처

4계층 구조:

```
System Prompt (고정 역할 + 8원칙)
    ↓
Platform Prompt (선택된 플랫폼만 동적 조립)
    ↓
User Context (description, preset, 미디어 분석)
    ↓
Output JSON Schema (strict mode, 선택된 플랫폼만 required)
```

API 호출은 **1회로 선택된 플랫폼 전체 캡션을 동시 생성**한다. 메시지 일관성 + 비용 절감.

---

## System Prompt (코드 하드코딩, 한국어)

다음 요소를 포함:

**역할 정의:**
> "당신은 한국 시장에서 활동하는 소셜 미디어 콘텐츠 전문 카피라이터입니다. 시청자의 클릭, 체류, 저장, 공유를 설계하는 사람입니다."

**핵심 원칙:**
1. 동일한 핵심 메시지를 유지하되, 플랫폼별 톤·구조·길이는 완전히 다르게.
2. 네이티브 사용자가 자연스럽게 느끼는 문체. 번역체·광고문구체 금지.
3. 해시태그 전략은 플랫폼별로 다름:
   - YouTube: 검색 SEO 중심 (검색되는 키워드)
   - Instagram: 발견 + 커뮤니티 (다양한 크기 믹스)
   - TikTok: 바이럴 트렌드 중심 (적은 수, 짧고 강한 태그)
4. 한국어 작성. 해시태그는 한/영 자연 혼합.
5. **클릭베이트 금지** — 거짓 약속, 과장된 충격 표현, 본문과 관련 없는 hook은 알고리즘과 사용자 모두에게 처벌됨.

**8가지 클릭/체류/저장 원칙 (위 섹션 참조):**
- 시스템 프롬프트에 핵심 1문장씩 요약해서 주입.
- 각 플랫폼 프롬프트 안에서 해당 원칙을 어떻게 적용할지 구체 지시.

**플랫폼별 캐릭터:**
- YouTube: *친절한 전문가* — 정보를 신뢰감 있게, 결론까지 안내
- Instagram: *감성 크리에이터* — 일상의 디테일, 공감, 스토리텔링
- TikTok: *임팩트 트렌드세터* — 짧고 강하게, 패턴을 깬다

**출력 규칙:**
- JSON Schema 엄격 준수
- 글자수 한도 엄격 (코드에서 후처리 트리밍하지만 AI 단계부터 지켜야 자연스러움)
- 해시태그는 `#` 포함 문자열 배열
- 빈 문자열 금지

## Platform Prompt 상세

### YouTube

**제목 (title) — 최대 100자**
- 키워드 앞쪽 배치 (검색 알고리즘 우대)
- **Curiosity Gap** 적용 (결과 노출 + 방법 숨김)
- 숫자/구체정보 (Specificity Bias)
- 대괄호 `[ ]` 또는 파이프 `|`로 카테고리 표시 가능
- 어그로/낚시 금지 — CTR이 높아도 시청 완료율이 떨어지면 알고리즘이 처벌

**설명 (description) — 최대 5000자, 권장 500~1500자**

구조:
1. **첫 2~3줄**: 영상 핵심 요약 (검색 결과에 표시되는 부분이라 가장 중요)
2. **상세설명 3~5문장**: 영상에서 다루는 내용, **Open Loop** 활용 ("끝까지 보면...", "후반부에 가장 중요한 비밀이...")
3. **타임스탬프**: 길이 모르면 생략
4. **CTA**: 구독·좋아요·댓글 (Question-Driven 형태가 최적)

SEO 키워드를 자연스럽게 2~3회 반복.

**hashtags — 최대 15개**
- 핵심 3~5 + 카테고리 3~5 + 롱테일 5
- 검색 SEO 중심 (실제 사람들이 검색할 단어)

**category — 1개 추천**
- "교육", "엔터테인먼트", "라이프스타일", "뷰티/패션", "테크" 등

### Instagram

**caption — 최대 2200자, 권장 300~800자**

구조:
1. **첫 줄 (Hook)**: 강한 감정/질문/숫자 — **First-Line Hook 원칙** 필수. 마침표 X, 줄임표나 의도적 단절. "더보기" 유도가 알고리즘 핵심.
2. **본문 스토리텔링**: 일상의 디테일, 공감 포인트. 가운데점 `·` 또는 줄바꿈으로 호흡. 이모지 1~3개/문단.
3. **질문형 CTA**: "여러분은 어떻게 생각하세요?" 같은 답하기 쉬운 질문.
4. **해시태그 블록**: 본문 끝에 줄바꿈 후 정렬. 또는 첫 댓글로 분리(권장).

감성적·대화체. **Save-Worthy Framing** 자연스럽게 포함 ("이거 저장해두고 다시 보세요" 식).

**hashtags — 최대 20개**
- 대형(100만+) 3~5 + 중형(1~100만) 5~8 + 소형/니치(<1만) 5~7
- 한/영 혼합. 다양한 크기 믹스가 발견 알고리즘에 유리

**cover_text — 최대 50자**
- 릴스 커버에 들어갈 임팩트 한 줄
- **Pattern Interruption** 또는 **Curiosity Gap** 활용
- 이미지 게시면 빈 문자열

### TikTok

**caption — 최대 300자 (엄격, 해시태그 포함)**

구조:
1. **훅 (첫 단어/한 줄)**: **Pattern Interruption** 최우선. 일반적 표현 절대 금지. 예측 깨는 단어로 시작.
2. **본문 1~2문장**: 영상 내용을 짧게.
3. **해시태그 인라인**: 본문 안에 자연스럽게 `#태그` 형태로 포함. 별도 블록 없음 (TikTok 실제 UX와 동일).
4. **짧은 CTA** (선택): "Save해놓고 따라해봐" 같은 짧은 한 줄.

캐주얼 톤 (`~ㅋㅋ`, `~임`, `~인듯`). 이모지 0~2개. 유행어/밈 자연 활용. 격식체 금지.

**hashtags — 최대 5개 (별도 메타데이터)**
- caption 본문에서 자동 추출되는 백업 메타. AI가 caption 안에 사용한 해시태그를 그대로 hashtags 배열로 반환.
- 트렌드 1~2 + 주제 2~3
- 짧은 태그 (긴 태그는 caption 글자수만 잡아먹음)

> **참고:** TikTok에서 hook/sound_recommendation 별도 필드는 사용하지 않는다. hook은 caption 첫 단어로 통합, sound는 영상 자체에서 결정되므로 캡션 단계에서는 다루지 않는다.

## User Context (동적 조립)

다음을 user 메시지로 구성:

```
[캡션 스타일 가이드]   ← 사용자가 프리셋 선택했을 경우, 프리셋의 instructions
[사용자 입력 기본 설명] ← description (최대 500자)
[게시 대상 플랫폼]     ← selectedPlatforms 명시
[미디어 유형]          ← 단일 이미지 / 멀티 이미지(N장) / 영상

이 [이미지/영상]을 분석해 위 형식으로 캡션을 생성해주세요.
```

이미지는 vision content로 함께 전달 (`detail: low` — 비용 절감, 캡션 품질에 충분).

---

## Output JSON Schema (strict mode)

```ts
{
  youtube?:   { title, description, hashtags[], category }
  instagram?: { caption, hashtags[], cover_text }
  tiktok?:    { caption, hashtags[] }
}
```

`required`는 선택된 플랫폼만 동적 추가 (선택 안 한 플랫폼은 응답에 아예 안 옴).

---

## API 호출 구현

1. 선택된 플랫폼의 Platform Prompt만 조합
2. JSON Schema의 `required` 필드 동적 설정
3. Vision content (이미지/영상 첫 프레임) 함께 전달
4. **GPT-4o 호출 파라미터:**
   - `temperature`: 0.7 (기본), 0.85 (재생성 시)
   - `max_tokens`: 4000
   - `response_format: { type: "json_schema", strict: true }`
5. JSON 파싱 → zod로 검증
6. **후처리 검증** (다음 섹션)

## 후처리 검증 (코드 자동 처리)

AI가 글자수를 어겼을 때 안전망:

**YouTube:**
- `title` 100자 초과 → 마지막 단어 경계까지 트리밍 + `...`
- `description` 5000자 초과 → 마지막 문단 단위로 잘라냄
- `hashtags` 15개 초과 → 뒤에서 제거
- `#` 누락된 태그 → 자동 prepend

**Instagram:**
- `caption` 2200자 초과 → 트리밍
- `hashtags` 20개 초과 → 뒤에서 제거
- `cover_text` 50자 초과 → 트리밍 (말줄임 없이)

**TikTok:**
- `caption` 300자 초과 → 트리밍
- `hashtags`는 caption에서 정규식(`/#[^\s#]+/g`)으로 추출하여 동기화 (AI 응답과 별도로). 5개 초과 시 처음 5개만.
- `#` 누락된 태그 → 자동 prepend

## 프리셋 시드 데이터 (예시)

| 프리셋 | 톤·스타일 instructions |
|--------|----------------------|
| **제품 리뷰형** | 솔직하고 분석적으로. 장점·단점·구매 기준을 균형있게. 결론에 별점/추천도. |
| **튜토리얼형** | 친절하고 교육적인 톤. "초보자도 이해할 수 있도록" 의식. 단계별 구조. |
| **이벤트 홍보형** | 밝고 에너지 있게. 일자/장소/혜택을 명확히. Loss Aversion 적극 활용. |
| **브이로그형** | 편안하고 친근한 톤. "오늘은~" 식 일상 도입. 감정 표현 풍부하게. |
| **먹방/맛집형** | 생생하고 맛있는 묘사. 의성어/의태어. "진짜 미쳤어요" 같은 감탄. |

> 프리셋 instructions는 system/platform prompt 위에 *오버라이드 우선순위*로 삽입한다 (`[캡션 스타일 가이드]` 블록).

## 재생성 처리

사용자가 "다시 생성" 버튼을 누른 경우:

1. 동일 입력으로 재호출하되 `temperature` 0.7 → 0.85 (다양성 ↑)
2. 이전 응답을 `assistant` 메시지로 추가, 그 뒤 user 메시지로 *"위 결과와 다른 톤·각도로 다시 생성해주세요. 같은 정보를 다르게 풀어내거나 다른 hook 전략(Pattern Interruption / Curiosity Gap / Loss Aversion 등)을 시도해주세요."* 요청.
3. 같은 contentId의 `ai_captions` 컬럼을 UPDATE (새 row 생성 안 함 — dangling row 방지)
4. 플랫폼 개별 재생성도 향후 지원 가능 (현재는 전체 재생성만)
