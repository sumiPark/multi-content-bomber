시리즈 댓글 자동화

인스타에 시리즈 2화를 올리고 그 회차의 답글을 켜면, 1화에 댓글을 남긴 사람들에게 시리즈마다 정한 문구로 대댓글을 바로 달아주는 기능입니다. 가능한지, 무엇이 필요한지, 어떻게 만들었는지 정리했습니다.

가능

만들 수 있습니다. 먼저 정리할 조건이 세 가지 있습니다.

인스타 API는 내 게시물 목록, 게시물의 댓글 조회, 댓글에 대댓글 등록을 모두 지원합니다. 이 기능에 필요한 권한(instagram_business_manage_comments)은 MCB가 이미 계정을 연결할 때 함께 요청하고 있습니다.

  1. 1
    누구 계정에 쓰는지에 따라 검수가 갈립니다. 우리 팀이 소유·관리하고 앱에 등록한 계정에만 쓰면 Standard Access로 바로 동작합니다. 외부 고객 계정에도 쓰려면 이 기능으로 Meta 앱 검수(Advanced Access)를 받아야 합니다.
  2. 2
    MCB가 “이 게시물이 1화, 저 게시물이 2화”라는 걸 알아야 합니다. 업로드할 때 시리즈와 회차를 지정하는 방식을 권장합니다. 캡션을 AI로 보고 추정하는 방식은 틀렸을 때 엉뚱한 사람에게 답글이 달려서 위험합니다.
  3. 3
    인스타 쪽 제약이 있습니다. 댓글 속 링크는 눌리지 않고, 대댓글은 최상위 댓글에만 달 수 있으며, 같은 문구를 짧은 간격으로 많이 달면 스팸으로 제한될 수 있습니다. 문구를 여러 개 돌려쓰고 등록 속도를 조절해야 합니다.

동작 순서

지금 발행 파이프라인(GitHub Actions 워커)에 단계를 덧붙이는 구조입니다. 새 서버는 필요 없습니다.

  1. 2화 발행 성공워커가 인스타 게시를 끝내고 결과를 기록하는 시점에 시작합니다.worker/processors/publish-processor.ts
  2. 같은 계정의 1화 게시물 찾기시리즈 회차 정보에서 같은 인스타 계정에 올라간 직전 회차를 찾습니다. 계정이 여러 개면 계정마다 따로 처리합니다.
  3. 1화 댓글 불러오기한 번에 최대 50개씩, 다음 페이지가 없을 때까지 가져옵니다. 인스타는 최상위 댓글만 돌려줍니다.
  4. 걸러내기내 계정 댓글, 숨긴 댓글, 이번 회차 알림을 이미 받은 사람을 빼고, 한 사람이 여러 번 댓글을 달았으면 한 번만 남깁니다.
  5. 회차 답글 켜기회차는 답글이 꺼진 상태로 추가됩니다. 회차 목록의 스위치를 켜는 순간(또는 업로드할 때 켜고 올리면 올라간 직후) 바로 보내기 시작합니다. 끄면 남은 답글은 멈춥니다.
  6. 대댓글 등록시리즈 문구를 돌려쓰며 1~2분(무작위) 간격으로 하나씩 등록합니다. 한 번 실행에 다 못 끝내면 진행 위치를 저장하고 다음 실행이 이어받습니다.
  7. 결과 기록보낸 답글, 건너뛴 이유, 실패 사유를 남겨 시리즈 화면에서 확인합니다. 같은 댓글에 두 번 달리지 않게 하는 기준도 이 기록입니다.

권한과 검수

  • 필요한 권한은 instagram_business_basic와 instagram_business_manage_comments 두 가지이고, 둘 다 이미 OAuth 요청 목록에 있습니다(lib/platforms/instagram.ts). 연결된 계정 토큰에 실제로 부여됐는지는 1단계에서 직접 호출해 확인합니다.
  • 호출 주소는 지금 발행에 쓰는 graph.instagram.com/v23.0 그대로입니다. 새 앱이나 새 로그인 방식은 필요 없습니다.

화면

사용자가 보는 곳

  • 자동화 › 시리즈 댓글 자동화: 위쪽에서 인스타 계정을 고르면 그 계정의 시리즈와 보낸 기록이 한 화면에 나옵니다. 보내는 중인 회차가 있으면 15초마다 진행 상황이 새로고침됩니다.
  • 새 시리즈: 이름과 답글 문구를 정하고(기본 문구 3개가 채워져 있음), 이미 올린 회차가 있으면 게시물 그리드에서 1화부터 순서대로 누르면 끝입니다. 누른 순서가 회차 번호가 됩니다.
  • 회차 답글 스위치: 회차마다 답글 켜기/끄기가 있고, 옆에 “보내는 중 120/327”, “327명에게 보냄”처럼 진행 상황이 보입니다. 새로 추가한 회차는 꺼진 상태이고, 켤 때 한 번 확인 창이 뜹니다. 첫 회차는 이전 화가 없어서 스위치가 없습니다.
  • 업로드 마법사: 마지막 단계에 “다음 화로 올리기”가 생깁니다. 선택한 인스타 계정에 시리즈가 있을 때만 보이고, “올라가면 바로 N화 댓글에 답글 달기” 체크박스로 켜고 올릴 수 있습니다(기본 꺼짐).
  • 다음 화 추가: MCB 밖에서 올린 회차도 게시물 그리드에서 골라 추가합니다. 꺼진 상태로 추가되니 준비되면 스위치를 켜면 됩니다.
  • 하루 최대 답글 수: 계정 설정은 이것 하나라 계정 머리에 한 줄로 두었습니다(기본 150개, 150개를 넘기면 경고). 보내는 방식은 바로 보내기로 고정이라 설정이 없습니다.
문구

답글 문구는 관리자가 등록합니다

  • 수정 권한: ADMIN과 MANAGER만 등록·수정·삭제할 수 있고, STAFF는 보기만 합니다. 계정 관리와 같은 기준입니다.
  • AI로 새로 만들기: 문구를 고칠 때 버튼을 누르면 친근한 해요체 문구 5개를 새로 만들어 채웁니다(누를 때마다 바뀜, 이모지는 일부 문구에만 1개). 링크·해시태그·다른 계정 멘션·홍보성 단어·연속 느낌표가 들어간 문구는 버리고, 시리즈 이름은 {series}로 바꿔 넣습니다. 저장은 사람이 누릅니다.
  • 시리즈별 문구: 시리즈를 만들 때 문구를 정하고, 시리즈 카드의 “문구 수정”으로 언제든 바꿉니다. 시리즈마다 말투와 내용을 다르게 쓸 수 있고, “기본 문구로” 버튼으로 되돌릴 수 있습니다.
  • 변수: {username}은 댓글 단 사람, {series}는 시리즈 이름, {episode}는 새 회차 번호입니다. 보낼 때 실제 값으로 바뀝니다.
  • 돌려쓰기: 등록한 문구를 순서대로 돌려가며 씁니다. 같은 문구만 반복하면 스팸 제한에 걸리기 쉬워서 2~3개 이상을 권장하고, 1개만 있으면 저장할 때 경고합니다.
  • 미리보기: 문구를 고치는 동안 가상의 댓글에 실제로 어떻게 달리는지 바로 보여줍니다.

워커

답글은 별도 워크플로에서 보냅니다

  • 댓글 API는 lib/platforms/instagram-comments.ts로 분리했습니다. 답글은 “잠시 제한됨(368)”과 “댓글이 지워짐”을 따로 다뤄야 해서 발행 어댑터와 에러 분류가 다릅니다.
  • 발행 워커는 “다음 화” 발행에 성공하면 회차를 기록하고 알림 작업만 만듭니다. 실제 수집·발송은 .github/workflows/episode-alerts.yml(worker/process-alerts.ts)이 합니다.
  • 워크플로를 나눈 이유: 답글은 1~2분 간격이라 실행이 길어서, 발행과 같은 직렬 그룹이면 그동안 즉시 발행이 줄을 섭니다.
  • 알림 워크플로는 발행 실행이 끝날 때마다 따라 돌고, “보내기”를 누르면 바로 깨어납니다. 40분 안에 못 끝내면 남은 건 다음 실행이 이어받고, 스스로 다음 실행을 깨웁니다.
  • 작업을 집어가는 방식은 발행과 같은 FOR UPDATE SKIP LOCKED RPC라 중복으로 보내지 않습니다.
  • 새 댓글 확인은 GitHub 예약 실행(실측 2~5시간씩 밀림) 대신 Supabase pg_cron이 5분마다 앱의 /api/cron/episode-replies를 부릅니다. 앱은 게시물 댓글 수가 늘었을 때만 댓글을 다시 읽고, 보낼 사람이 생겼을 때만 GitHub 답글 워커를 깨웁니다. 호출 인증용 비밀값은 마이그레이션이 Vault에 직접 만들어 저장소에 남지 않습니다.

제약과 대응

제약영향대응
댓글 링크가 눌리지 않음답글에 2화 주소를 넣어도 클릭이 안 됩니다문구를 “프로필에서 확인”으로 유도합니다. 링크가 꼭 필요하면 비공개 답장(DM)을 선택 기능으로 붙입니다

진행 순서

1~4단계는 2026년 10월 13일에 구현했습니다. 배포 전에 마이그레이션 0017을 Supabase에 적용해야 합니다.

1단계 · 권한과 API 직접 확인

완료
  • 연결된 인스타 계정 4개 모두 댓글 조회 성공 (작성자 이름·숨김 여부 포함) — 우리 계정에는 추가 검수 없이 동작
  • 댓글 653개 게시물에서 수집·분류 드라이런: 답글 325개 제외, 대상 327명
  • 남은 확인: 테스트 게시물에 실제 대댓글 1개 (배포 후 테스트 시리즈의 2화 답글을 켜서)

2단계 · 시리즈 데이터와 업로드 마법사

완료
  • 마이그레이션 0017 (테이블 5개 + RLS + RPC 2개)
  • 마법사에 시리즈·회차 지정, 발행 성공 시 회차와 인스타 게시물 연결

3단계 · 인스타 게시물 불러오기와 시리즈 화면

완료
  • 내 게시물 목록에서 골라 회차로 지정
  • 계정별 화면, 시리즈 관리, 시리즈별 답글 문구 편집(미리보기, 기본 문구)

4단계 · 답글 작업, 켜기/끄기, 기록

완료
  • 워커 답글 처리 단계, 작업 선점 RPC, 이어받기, 속도 조절
  • 회차별 답글 스위치(기본 꺼짐, 켜면 바로 보내기)와 보낸 기록 화면

5단계 · 새 댓글 이어서 보내기

완료
  • 답글을 켠 뒤 7일 동안 5분마다 직전 화 새 댓글을 확인해서 보냄 (Supabase pg_cron, 마이그레이션 0020)
  • 7일이 지나면 다 보낸 회차의 답글 스위치가 자동으로 꺼지고 “7일 지나 꺼짐”으로 표시 (0021). 기간은 일단 7일 고정
  • 최신화 소식을 이전 회차 댓글에도: 최신화 답글을 켤 때 확인창에서 고르고, 켠 뒤엔 “1~N-2화 댓글에도” 스위치로 켜고 끔. 가장 최근 화에 단 댓글에 하나만, 이미 받은 사람·이번 화에 댓글 단 사람은 빼고, 같은 댓글엔 최신화 소식 하나 (0023)
  • 보내는 순서: 최근 화 댓글부터(같은 화 안에서는 최근 댓글부터) — 하루 상한에 걸려도 최근 독자가 먼저 받음
  • 최신화가 아닌 회차 스위치를 켜면 “N화 올라왔어요”로 나간다고 경고
  • 이전 화 스위치를 끄면 직전 화 답글은 그대로 두고 이전 화 쪽만 멈춤. 보내는 중에도 켜고 끌 수 있고, 워커는 보내기 전 배치마다 스위치를 다시 확인해 모으던 중에 꺼도 멈춘다
  • 남은 것(선택): 댓글 웹훅으로 실시간 처리, 비공개 답장(DM) 옵션

병행 · 외부 계정에 쓸 경우 Meta 검수

영업일 5~7일

4단계까지 만든 화면으로 시연 영상을 찍어 Advanced Access를 신청합니다. 우리 팀 계정에만 쓴다면 건너뜁니다.

정해야 할 것

오른쪽은 따로 말씀이 없으면 적용할 기본값입니다.

  • 어떤 계정에 쓰나요?우리 팀 계정만으로 시작하면 검수 없이 바로 쓸 수 있습니다
  • 자동으로 보낼까요, 확인 후 보낼까요?바로 보내기로 고정. 대신 회차마다 답글 스위치가 있고 기본은 꺼짐
  • 어느 회차 댓글에 알릴까요?기본은 직전 회차만 (2화가 나오면 1화, 3화가 나오면 2화). 최신화 답글을 켤 때 확인창에서 “이전 화 댓글에도 보내기”를 고르면 1~(N-1)화 전체 — 켠 뒤에도 “1~N-2화 댓글에도” 스위치로 켜고 끔. 한 사람에게 하나, 최근 화 댓글부터 보내고, 다음 화가 올라오면 이전 화 쪽은 멈춤 (0023)
  • 어떤 댓글까지 대상인가요?켜는 순간까지의 댓글 + 켜진 7일 동안 새로 달린 댓글. 7일이 지나면 자동으로 꺼짐
  • 공개 대댓글과 DM 중 무엇으로?공개 대댓글. 다른 사람들에게도 2화 소식이 보이는 효과가 있습니다
  • 답글 문구는요? 관리자가 시리즈마다 등록합니다. 새 시리즈엔 아래 3개가 기본으로 채워져 있습니다 @{username} {episode}화 올라왔어요! 프로필에서 바로 보실 수 있어요 @{username} 기다리셨죠? {series} {episode}화 업로드됐어요 @{username} {episode}화 나왔어요. 프로필 최신 게시물에서 확인해주세요
