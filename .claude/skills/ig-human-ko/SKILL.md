# ig-human-ko

영어판 `ig-human`의 한국어 각색(원본 고지 `../ig-ko-LICENSE.md`). 도구 둘은 실제로 돈다.
눈대중으로 하지 말고 돌려라. 프로젝트 루트에서:

```bash
python -I .claude/skills/ig-human-ko/humanize_ko.py draft.txt --report      # 고치고, 무엇을 바꿨는지
python -I .claude/skills/ig-human-ko/detect_ko.py draft.txt                 # 다섯 검사 채점
python -I .claude/skills/ig-human-ko/detect_ko.py before.txt after.txt      # 전후 비교
```

둘 다 `slop_ko.json`을 읽는다: 상투어 단어 58개·구절 45개(대체 제안 포함), 자동 치환하는
번역투 13개, 보이지 않는 문자 22종, 타이포 9종, 구조적 티 19종, 구어 표지 4종. 고쳐 쓰라고
만든 파일이다. 사용자가 늘 쓰는 말이 걸리면 그 항목을 지워라.

## 인스타에서 이게 더 중요한 이유

캡션은 짧고 대본은 소리 내어 읽힌다. 600자 캡션 속 글말 한 줄은 긴 글 속 같은 한 줄보다
훨씬 크게 보이고, 아무도 자연스럽게 못 읽을 보이스오버는 첫 테이크에서 티가 난다. 진짜
문제는 탐지기가 아니라, 스크롤하던 사람이 "광고 문구네" 하고 넘기는 것, 그리고 말하는
사람이 자기 대본에서 혀가 꼬이는 것이다.

## 자동으로 고치는 것 (기계적으로 안전한 것만)

**1. 보이지 않는 문자.** 폭 없는 공백·결합 문자, BOM, 소프트 하이픈, 태그 문자, 한글 채움
문자(U+3164), 특수 공백. 키보드는 이걸 안 만든다. 전부 지운다(특수 공백은 일반 공백으로).
단, 조합 이모지(👩‍👧) 안의 ZWJ는 이모지를 깨뜨리지 않게 남긴다.

**2. 타이포.** em dash(—)·가로줄(―)은 쉼표로(종결 어미 뒤면 마침표로), 숫자 사이 en dash는
물결(5–10분 → 5~10분), 둥근 따옴표는 곧은 따옴표, 줄임표 문자(…)는 마침표 셋, •는 -.
가운뎃점(·)과 화살표(→)는 한국어에서 사람이 흔히 쓰므로 둔다.

**3. 명백한 번역투만.** 문법이 안 깨지는 것만 바꾼다:
~함에 있어(서) → ~할 때, ~에 있어서 → ~에서, ~을/를 통해 → ~(으)로(받침 맞춤),
~하는 것이 가능합니다 → ~할 수 있습니다, 되어집니다 → 됩니다(이중 피동),
~하도록 하겠습니다 → ~하겠습니다, ~에 위치한 → ~에 있는, ~하기 위해서 → ~하려고.

## 자동으로 안 고치는 것 (제안만)

한국어는 조사·어미가 붙어서 단어를 기계적으로 바꾸면 문장이 깨진다. 그래서 아래는
**보고서에 위치와 대체 제안만** 나온다. 고르는 건 네 몫이다.

- 상투 형용사: 다양한, 특별한, 완벽한, 놀라운, 혁신적인, 엄선된, 프리미엄 …
- AI 상투: 선사합니다, 경험해 보세요, ~의 정석, 여정, 빛나는, 한 단계 업그레이드 …
- 광고 상투: 놓치지 마세요, 강력 추천, 인생템, 꼭 써 보세요, 후회 없는 선택, 역대급 …
- 접속 상투: 결론적으로, 또한, 뿐만 아니라, 이처럼, 따라서, 무엇보다 …
- 서두·맺음 상투: "~고민이신 분들 많으시죠?", "오늘은 ~에 대해 알아보겠습니다",
  "도움이 되셨길 바랍니다"
- 과한 정중함: ~해 주시면 감사하겠습니다, ~하시길 바랍니다
- 번역투(문맥 판단 필요): ~에 대해, ~에 대한, ~라고 할 수 있습니다, ~에 의해, ~를 진행합니다

구조적 티도 **표시만** 한다. 문장 모양을 바꾸려면 판단이 필요하다:

- "단순한 X가 아니라 Y", "X뿐만 아니라 Y까지", "중요한 건 X가 아니라 Y"
- 기계적 나열("첫째, 둘째, 셋째"), 셋 묶음("A, B, 그리고 C")
- 한 줄 수사 의문("결과는?"), 글짓기식 맺음("결론적으로")
- 영상·글 서두, "스크롤 멈춰" 시작, 반사적 팔로우·태그 유도, 느낌표 남발
- 이모지 글머리표, 로켓·불·반짝이 이모지, 해시태그 벽
- **같은 어미 3문장 연속**("~습니다. ~습니다. ~습니다.")과 너무 고른 문장 길이
- 광고 심의 위험 표현(치료, 완치, 재생, 염증, 최고, 유일, 100%, 부작용 없음, 질병 예방)

이 목록이 네 일이다. 뜻은 살리고 표시된 줄을 손으로 다시 쓴 다음 `detect_ko.py`를 다시
돌린다. 점수를 REVIEW에서 PASS로 올리는 건 이 부분이고, 스크립트가 못 하는 부분이다.

## 다섯 검사

`detect_ko.py`는 다섯 신호를 0~100(높을수록 사람 같음)으로 매긴다:

| 검사 | 재는 것 | 기계 같은 모습 |
| --- | --- | --- |
| 길이 변화 | 문장 길이(음절) 변화 | 모든 문장이 같은 길이 |
| 구체성 | 100어절당 숫자·이름·인용 | 추상 명사, 숫자 없음 |
| 상투어 | 100어절당 사전 적중 | 상투어 범벅 |
| 타이포 지문 | 1천 자당 보이지 않는 문자·em dash 등 | 타이포가 너무 완벽 |
| 말투 | 구어 표지(~거든요, 근데, ㅋㅋ), 인칭, '~니다' 비율, 어미 반복, 구조적 티 | 전부 ~습니다, 무인칭, 연출된 반전 |

판정은 평균 60% + **가장 약한 검사 하나** 40%. 신호 하나면 충분하기 때문이다. PASS는 총점
70 이상이고 55 아래인 검사가 없어야 한다.

한국어판 기준값은 원본 영어 값을 어절 단위로 환산한 추정이다(1어절 ≈ 영어 1.6단어). 둥근
따옴표·줄임표 문자는 iOS 스마트 구두점이 한국어 자판에서도 만들어서 가볍게만 센다.

## 정직하게 말할 것

이건 공개 탐지기들이 보는 신호를 본뜬 로컬 휴리스틱 다섯 개다. 전부 사용자 컴퓨터에서 돌고
아무것도 업로드하지 않는다. GPTZero, 카피킬러, 무하유 GPT킬러 같은 서비스가 **아니고**, 그
API를 부르지 않으며, 그 판정을 약속할 수 없다. 이게 재는 걸 고치면 그 숫자들도 움직이는
경향이 있다, 같은 걸 재니까. 주장은 거기까지다. 사용자 대신 더 큰 주장을 하지 말고,
"탐지 안 됩니다"라고 말하지 마라. 한국어 실제 코퍼스로 맞춘 적도 없다.

## 순서

1. `humanize_ko.py draft.txt -o clean.txt --report`
2. 제안·구조적 티를 읽고 그 줄을 직접 다시 쓴다.
3. `detect_ko.py draft.txt clean.txt`로 전후를 보여 준다.
4. PASS가 아니면 출력이 짚은 가장 약한 검사부터 고치고 다시. 두 바퀴가 보통이다. 다섯 바퀴면
   초안이 공식으로 쓰인 거고, 답은 더 돌리는 게 아니라 다른 초안이다.
5. 사용자에게는 고친 글과 점수를 같이 보여 준다. 점수만 보여 주지 않는다.
